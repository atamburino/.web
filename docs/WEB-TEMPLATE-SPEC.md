# `.web` frontend template spec

Status: revision 4. Built locally in `/workspace/web-template/app`. Not pushed to GitHub. Versions were checked against the npm registry and nodejs.org on 2026-10-11.

## Purpose

`atamburino/.web` is a GitHub template repository. You create a new frontend from it, run one init command, and get a typed React app that talks to a BFF through generated, runtime-validated RTK Query hooks. shadcn/ui components, light and dark themes, routing, CI, lint rules, and Cursor rules come pre-wired. One reference feature, which is also the index page, shows the shape every new feature copies.

## Non-goals

- No SSR, no Next.js, no React Server Components. The app is a static SPA served next to a BFF.
- No TanStack Query. TanStack Router handles routing only. RTK Query owns all server data.
- No auth, i18n, analytics, or feature flags. Each app adds them if it needs them.
- No CI run against a real BFF yet. See "Future options".
- No monorepo. One app per repo.

## Decisions that change the starting defaults

1. **TypeScript 6.0.3, not 7.0.2.** TypeScript 7.0.2 is `latest` on npm. `typescript-eslint` 8.71.1 declares the peer range `typescript >=4.8.4 <6.1.0`, so type-aware lint does not support 7 yet. Move to 7 when that range widens.
2. **Two code generators from one spec.** `@rtk-query/codegen-openapi` generates endpoints and hooks but emits TypeScript types only, with no runtime check. `@hey-api/openapi-ts` generates zod schemas from the same spec. A generated `validation.gen.ts` attaches each schema to its endpoint through RTK Query's built-in `responseSchema` option (Standard Schema support, RTK 2.7+). Nobody hand-writes a schema for a BFF response.
3. **Vitest browser mode instead of jsdom.** Component tests run in real Chromium through Playwright. jsdom has no layout, no real Tailwind output, and no real `matchMedia`, so it cannot test themes or reduced motion. Testing Library-style queries still apply through `vitest-browser-react`.
4. **shadcn/ui as owned source.** The `shadcn` CLI copies components into `src/shared/ui/`. The app owns that code, and variants live there in `cva`. Feature code composes these components and never builds its own variant logic from raw classes.
5. **React Bits through the shadcn CLI.** React Bits is a copy-in collection with TypeScript and Tailwind variants, not an npm package. Components land in `src/shared/motion/bits/`. Features reach them only through `shared/motion`, which owns the reduced-motion gate. The React Bits registry name for the shadcn CLI is not verified.
6. **React Compiler on.** `@vitejs/plugin-react` 6 supports `babel-plugin-react-compiler` 1.x. The compiler removes most hand-written `useMemo` and `useCallback`, which keeps components short.
7. **TanStack Router with file-based routes.** The Vite plugin generates `routeTree.gen.ts` from `src/routes/`. Code-based routing needs a hand-assembled route tree, which is a second list of routes to keep in sync. File-based routing also gives automatic per-route code splitting.

shadcn's own file names are kebab-case (`button.tsx`). The template keeps them so `shadcn add` and `shadcn diff` keep working. Everything else uses PascalCase for components and camelCase for modules.

Each feature folder exposes only `index.ts`. ESLint (`eslint-plugin-boundaries`) fails the build in these cases:

- A file imports another feature's internals.
- A file other than a feature's `api.ts` imports `shared/api/generated`.
- A file other than `features/example/api.ts` imports `shared/api/generated/sample`.
- A file in `src/routes/` imports anything from a feature other than its `index.ts`.

### Strict tsconfig

`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `isolatedModules`, `moduleResolution: "bundler"`, `noEmit`, `paths: { "@/*": ["./src/*"] }` for the shadcn aliases.

### Lint rules beyond the presets

- `@typescript-eslint/consistent-type-assertions` with `assertionStyle: "never"`. This bans `as`. Generated files are exempt. A shadcn component that needs a cast gets fixed when it is added.
- `@typescript-eslint/no-explicit-any`, `no-floating-promises`, `switch-exhaustiveness-check`, `strict-boolean-expressions`.
- `no-console` as an error.
- `no-restricted-syntax` bans the JSX `style` prop outside `shared/motion`.
- `no-restricted-imports` blocks `@tanstack/react-query` everywhere, and blocks `motion`, `gsap`, and `shared/motion/bits/*` outside `shared/motion`.
- `max-lines` 200 per file and `max-lines-per-function` 60, as warnings. CI runs with `--max-warnings 0`, so warnings block a merge. `shared/ui` is exempt from both, because shadcn files are upstream-shaped.

### Tailwind lint

`eslint-plugin-better-tailwindcss` reads the Tailwind v4 CSS entry (`globals.css`) and lints class strings in `className`, `cn()`, and `cva()` calls.

- `no-unknown-classes` and `no-conflicting-classes` catch typos and classes that cancel each other.
- `no-duplicate-classes` and `no-deprecated-classes` as errors.
- `no-restricted-classes`, outside `src/shared/ui/**` only, bans three patterns:
  - Arbitrary values such as `text-[#fff]` or `w-[37px]`. The rule's docs give the pattern `\[([^\[\]]*?)\](?!:)`.
  - Raw palette colors such as `bg-blue-500`. Use the semantic tokens (`bg-primary`, `text-muted-foreground`).
  - Literal durations such as `duration-300`. Use the motion utilities from `globals.css`.
- The plugin's own class-order rule is off. `prettier-plugin-tailwindcss` sorts classes, so there is one sorter.

Prettier formats code and sorts classes. ESLint owns correctness. Biome was considered and rejected because it lacks the type-aware rules above.

## API and codegen flow

1. `template.config.ts` holds one `apiUrl`. The default is `https://localhost:5001/openapi/v1.json`, the ASP.NET Core built-in OpenAPI path. `init` sets the host.
2. `pnpm api:pull` fetches `apiUrl` and writes `api/openapi.json`. You commit the file. This is the only command that talks to the BFF.
3. `pnpm api:gen` reads only the committed spec files. For each of `openapi.json` and `sample.openapi.json`, it runs three steps:
   - `@rtk-query/codegen-openapi` writes `endpoints.gen.ts`. It injects endpoints into the empty `baseApi` and exports hooks.
   - `@hey-api/openapi-ts` with its zod plugin writes `schemas.gen.ts`.
   - `scripts/gen-validation.ts` writes `validation.gen.ts`. That file calls `enhanceEndpoints` once and sets `responseSchema` for every operation that has a JSON response. The script derives the mapping from `operationId`, so no list is kept by hand.
4. CI never fetches the spec. It reruns `pnpm api:gen` and fails on `git diff --exit-code`. A spec change with stale generated code cannot merge.

`sample.openapi.json` defines one operation, `getTemplateSampleItems`. The unusual name avoids a clash with real endpoints injected into the same `baseApi`. Because the sample spec never changes on `api:pull`, `features/example` always compiles.

Schema failures go through `catchSchemaFailure` in `baseApi.ts` and become an `ApiError`:

```ts
type ApiError =
	| { kind: "network"; message: string }
	| { kind: "http"; status: number; body: unknown }
	| { kind: "validation"; endpoint: string; issues: readonly SchemaIssue[] };
```

`toApiError` is the one function that builds this type. Components switch on `kind` with an exhaustive `never` default.

Risk to verify while building: hey-api's zod output names (`z<OperationId>Response`) must line up with RTK codegen's endpoint names. If they do not, `gen-validation.ts` maps by `operationId` from the spec directly.

## Routing

TanStack Router owns the URL. RTK Query owns server data. The template does not install TanStack Query, and lint blocks its import. Neither library stores the other's state.

- Route files in `src/routes/` hold only wiring: `createFileRoute`, `validateSearch`, an optional `loader`, and `component`. Each takes about 10 lines. Logic and markup live in the feature.
- Each feature owns its search schema in `search.ts` and exports it from `index.ts`. The route passes the schema straight to `validateSearch`. Every field uses `.default()` for an absent value and `.catch()` for an invalid one, so a bad URL renders defaults instead of an error page.
- `Route.useSearch()` returns the parsed type. Components never read `window.location`.
- `router.ts` declares the `Register` interface, which types every `Link`, `navigate`, and `useSearch` call. A link to a route that does not exist fails `tsc`.
- The root route carries `{ store: AppStore }` as router context. A loader that wants data before render calls `context.store.dispatch(api.util.prefetch(...))`. The component still reads the data through the RTK Query hook, so the RTK Query cache stays the one owner.
- `routeTree.gen.ts` is committed, exempt from ESLint and Prettier, and covered by the CI drift check.

## State and data patterns

- **Server state lives only in the RTK Query cache.** No slice copies a response. One owner per piece of state.
- **URL state lives only in search params**, parsed by the route. No slice mirrors it.
- **Theme state lives in `ThemeProvider`** and `localStorage`. It is the only client state the template ships.
- **Client state that crosses features** goes in a slice inside the owning feature, registered in `app/store.ts`. Local UI state stays in `useState`.
- **The feature's `api.ts` is the boundary.** It re-exports the generated hooks the feature uses and maps DTOs to domain types through pure functions in `model.ts`, such as `toOrder(dto): Order`. Components never see a DTO type.
- **Brand ids in `model.ts`** (`OrderId = string & { readonly __brand: "OrderId" }`) where two ids could be swapped. Brand only where a mix-up is possible.
- **Model variants as discriminated unions.** A request is `{ kind: "loading" } | { kind: "error"; error: ApiError } | { kind: "ready"; data: T }`, built once by `toRequestState` from the RTK Query hook result.
- **Environment variables** pass through `config/env.ts` once at startup. A missing `VITE_BFF_URL` fails at boot with the zod issue, not on the first request.
- **Typed hooks** come from `useDispatch.withTypes<AppDispatch>()` and `useSelector.withTypes<RootState>()`.
- **Pass objects, not positional arguments**, to any function with two or more parameters.

## Styling and motion

- `globals.css` is the only CSS file. It holds `@import "tailwindcss"`, `@import "tw-animate-css"`, shadcn's light tokens on `:root`, dark tokens on `.dark`, and the `@theme inline` block that maps them to utilities. There is no `tailwind.config.js`.
- Light and dark ship from day one through shadcn's standard theme. The dark theme is one extra block of about 30 custom properties, so it adds little. `ThemeProvider` sets `.dark` on `<html>`, follows the system setting by default, and stores an override in `localStorage`.
- Variants live in `cva` inside `shared/ui`. A feature that needs a new look adds a variant to the shared component instead of stacking classes at the call site.
- `cn()` in `shared/lib/cn.ts` is the one way to merge classes. It runs `tailwind-merge` over `clsx`, so a caller's class overrides a component default instead of conflicting with it.
- Feature code uses semantic tokens and layout utilities only. Arbitrary values, raw palette colors, and literal durations fail lint outside `shared/ui` (see "Tailwind lint").
- Motion durations are tokens. `globals.css` defines `--duration-fast`, `--duration-base`, and `--duration-slow`, and exposes them as `@utility` classes (`transition-fast` and the rest). Under `@media (prefers-reduced-motion: reduce)` every duration token becomes `0ms`, so app transitions honor reduced motion with no per-component code.
- shadcn components keep their upstream literal durations and `tw-animate-css` animations, which the tokens do not reach. For those, the same media block in `globals.css` sets `transition-duration` and `animation-duration` to `0ms` on every element. This block is the single backstop. Feature code still uses the tokens.
- `providers.tsx` wraps the app in `<MotionConfig reducedMotion="user">`. Every `motion` component then honors `prefers-reduced-motion`.
- Some React Bits components animate with GSAP or canvas, and neither CSS nor `MotionConfig` reaches them. `<Animated fallback={...}>` reads `useReducedMotion()` and renders the static fallback when the user asks for reduced motion. The `fallback` prop is required, so a component cannot skip it.
- A browser test emulates `prefers-reduced-motion: reduce` and asserts that the fallback renders. A second browser test toggles the theme and asserts that `.dark` lands on `<html>`. Whether Vitest browser mode can emulate the media query directly is not verified. If it cannot, the test runs in a Playwright context with `reducedMotion: "reduce"`.

## Testing

Vitest runs two projects from `vite.config.ts`:

- `unit` runs in Node. It covers pure functions in `model.ts`, `toApiError`, `toRequestState`, and search schemas. These need no mocks because they have no I/O.
- `browser` runs in real Chromium. It renders feature routes with the real router, the real store, real RTK Query, real zod validation, and real Tailwind output.

**The network is the one fake.** The template has no BFF, so browser tests use MSW 3 as a fake BFF. The fetch, the cache, and the validation all run for real. Only the server is fake. To keep the fake honest, every fixture passes through the generated zod schema in `test/server.ts` before MSW returns it. A fixture that drifts from the spec fails the test.

MSW does not catch BFF logic bugs, wrong status codes, or auth behavior. The committed spec plus the CI drift check catch contract drift and nothing more.

Naming: `*.test.ts` runs in `unit` and `*.browser.test.tsx` runs in `browser`. Tests live next to the code they test.

## CI

`.github/workflows/ci.yml` runs on `pull_request` and on pushes to `main`, with `concurrency` set to cancel superseded runs. CI makes no network call to a BFF.

1. `pnpm install --frozen-lockfile`. Node comes from `.nvmrc`. pnpm and Playwright Chromium are cached.
2. Run the following steps in parallel jobs:
   - `pnpm typecheck` runs `tsc -b`.
   - `pnpm lint` runs `eslint . --max-warnings 0`.
   - `pnpm format:check` runs `prettier --check .`.
   - `pnpm test` runs both Vitest projects.
   - `pnpm build` runs `vite build`, then `git diff --exit-code src/routeTree.gen.ts`.
   - `pnpm api:gen` followed by `git diff --exit-code`.
3. On the template repo only (`if: github.repository == 'atamburino/.web'`), an extra job runs `init` and `new:feature` into a temp copy and then runs steps 1 and 2 there. A template that cannot initialize or scaffold cannot merge.

Dependabot opens one grouped npm update and one GitHub Actions update each month. shadcn components are not npm dependencies, so `pnpm dlx shadcn diff` is the manual way to see upstream changes.

## Create a new app from the template

1. Run `gh repo create atamburino/my-app --template atamburino/.web --private --clone`.
2. Run `pnpm install`.
3. Run `pnpm init:app --name my-app --title "My App" --api-host https://localhost:5001`.

`scripts/init.ts` runs on Node 24 type stripping, with no build step. It does the following:

- Parses its flags with zod. `--name` must be a valid npm package name. The template's own `package.json` name is `web-template`, because npm rejects names that start with a dot.
- Writes `apiUrl` in `template.config.ts` as `<api-host>/openapi/v1.json`. Pass `--api-url` instead to override the full URL.
- Replaces the placeholders listed in `template.config.ts` in `package.json`, `index.html`, `README.md`, and `.env.example`. That file is the only list of placeholders.
- Runs `pnpm api:pull` and `pnpm api:gen` when the BFF is reachable. If it is down, init skips this step and prints the commands to run later. The sample spec and `features/example` work either way.
- Keeps `features/example` and `api/sample.openapi.json`.
- Deletes `scripts/init.ts`, the `init:app` script, and the template-only CI job. `template.config.ts` stays because it holds `apiUrl`.
- Refuses to run twice. Init writes `initialized: true` into `template.config.ts` and exits when it finds it.
- Prints the remaining manual steps, such as setting branch protection.

Mark the repo as a template in **Settings > General > Template repository**. Do this once, by hand or with `gh repo edit atamburino/.web --template`.

## Add a feature

`features/example` is the canonical reference slice and renders the index route `/`. It ships in production builds. Each app replaces or extends it with its first real screen. It is the shape to copy, and it stays small enough to read in one sitting: one endpoint, one model mapper, one search schema, one page built from `shared/ui`, and one test of each kind.

`pnpm new:feature orders` runs `scripts/new-feature.ts`, about 40 lines. It does the following:

1. Copies `features/example` to `features/orders`.
2. Renames `Example` to `Orders` and `example` to `orders` in file names and file contents. It does nothing else.
3. Copies `routes/index.tsx` to `routes/orders.tsx` with the same rename, routes it at `/orders`, and points the copied browser tests at `/orders`.
4. Regenerates `routeTree.gen.ts` with `tsr generate`.
5. Refuses to run if `features/orders` already exists.

The new `api.ts` still imports from `generated/sample`, which only `features/example/api.ts` may import. Lint fails until you point it at the real generated hook. That failure is the to-do list. The script holds no templates of its own, so it cannot drift from the reference slice.

## Cursor and Claude Code rules

- `.cursor/rules/typescript.mdc` holds the pstack `typescript-best-practices`, `principle-type-system-discipline`, and `principle-boundary-discipline` rules, trimmed to the rule tables.
- `.cursor/rules/frontend-architecture.mdc` holds the slice, API, routing, state, and styling rules from this spec. It names `features/example` as the file set to copy and `pnpm dlx shadcn add` as the way to add a UI component.
- `AGENTS.md` links to both files instead of copying them, so the rules live in one place.
- Code comments are rare. A comment explains a non-obvious reason, never what the next line does.

## As-built deviations

- shadcn CLI 4.21.4 generates components that import `cn` from the `cn` package (shadcn's replacement for `clsx` plus `tailwind-merge`). The template uses it and has no `shared/lib/cn.ts`. The shadcn base is `radix` with the `nova` preset.
- Import boundaries use ESLint's built-in `no-restricted-imports` instead of `eslint-plugin-boundaries`. A feature's `model.ts` may import generated types as well as its `api.ts`.
- Both code generators run from `scripts/gen-api.ts`. The list of specs lives in `scripts/apiSpecs.ts`, so there are no separate generator config files.
- `<Animated>` uses a `useSyncExternalStore` hook over `matchMedia` instead of motion's `useReducedMotion`, which cached its first value.
- MSW serves the sample endpoint in dev, in tests, and in `pnpm build:standalone`. `pnpm build` excludes MSW.
- The production bundle is about 631 kB minified (204 kB gzip), so Vite prints its 500 kB chunk warning.
